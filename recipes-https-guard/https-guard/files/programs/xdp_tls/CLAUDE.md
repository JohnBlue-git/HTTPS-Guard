# xdp_tls/ — AUXILIARY hook

XDP program on the NIC RX path — inspects TLS ClientHello and plaintext-HTTP-on-443 traffic at the wire, before any TCP/TLS handshake completes. The only hook whose synchronous enforcement power (`XDP_DROP` for a known-bad source or a downgraded ClientHello) is actually reachable in practice, and the only place `blocklist_check()` (shared with `../../actions/blocklist/`) runs — `../lsm_cert_guard/` also decides synchronously in-kernel by design, but currently can't attach at all on ARM32/AST2600 (no BPF trampoline support), so its deny branch is unreachable there regardless of its own shadow-mode flag.

**Read `DESIGN.md` in this directory before touching this hook's logic** — it covers why wire-level inspection catches things the uprobe fundamentally can't, the exact ClientHello byte layout this hook parses, and the two-tier synchronous/asynchronous enforcement flow with diagrams.

Beyond `legacy_version`, the ClientHello parse also extracts the offered **cipher suite list** and the **SNI host_name**, classified by `../../detections/cipher_suite/` and `../../detections/sni/` — like every rule, they live in the classification tree rather than in this hook, even though only this hook can feed them. Both are alert-only on purpose: the XDP blocklist drops a source IP across *all* ports, so enforcing on them would let one odd handshake lock an administrator out of SSH — see `CipherSuiteDetector`'s class comment for the incident that settled this.

Known gaps: no rate-based detection yet (planned as a separate, stateful mechanism); the XDP attachment leaks across daemon restarts, silently disabling this whole hook until reboot (tracked in `.scratch/`).

`src/XdpTlsProgram.{hpp,cpp}` implements `IHookModule` (see `../CLAUDE.md`); `ebpf/xdp_tls.bpf.h` / `ebpf/xdp_tls_event.h` are the BPF-side program and its raw event struct, including the native→generic→skip attach fallback's BPF-side half (the attach calls themselves are in `XdpTlsProgram.cpp`). `ebpf/parse_client_hello.h` holds the cipher-suite/SNI walk, kept deliberately dependency-free so the *same* code the kernel runs is unit-tested host-side (`../../tests/test_client_hello_parsing.cpp`) — and its byte-at-a-time read helpers exist to satisfy the BPF verifier, which rejected the straightforward version; don't "simplify" them without reading why.
