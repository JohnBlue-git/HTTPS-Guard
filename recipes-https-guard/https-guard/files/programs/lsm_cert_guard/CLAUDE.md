# lsm_cert_guard/ — AUXILIARY hook

BPF-LSM hook on the "file_open" security hook, filtered to one path: the BMC's HTTPS certificate/key file (`/etc/ssl/certs/https/server.pem`). Unlike `ssl_uprobe`'s comm-based process reporting, this hook's whole reason to exist is a *stronger* identity check — but the strong check (the accessing process's real executable, not self-reported `comm`) turns out to only be resolvable in userspace on this platform, not in-kernel; see `DESIGN.md` for why.

**Currently fails to attach on ARM32/AST2600 (this project's actual target).** `bpf_program__attach_lsm()` returns `-ENOTSUPP` here — not a bug in this hook, but a hard architecture gap: `arch/arm/net/` (the ARM32 BPF JIT) never implemented `arch_prepare_bpf_trampoline()`, and `BPF_PROG_TYPE_LSM` attach fundamentally requires a trampoline, the same mechanism `fentry`/`fexit` use. No BPF-program-level change can work around this. `LsmCertGuardProgram::attach()` returns `false` non-fatally, the same way `xdp_tls` degrades gracefully when XDP isn't available — the daemon still runs on the other two hooks.

**Read `DESIGN.md` in this directory before touching this hook's logic** — it covers the full identity-check story: why a first version (resolving the real exe path in-kernel via `task->mm->exe_file` + `bpf_d_path()`, then the kernel-recommended `bpf_get_task_exe_file()` kfunc) failed at increasingly fundamental layers (verifier trust, then JIT kfunc-call support, then trampoline attach itself), why shadow mode's deny branch is real code but not expected to ever become safely reachable on this hardware even if flipped on, and what the rollout plan actually is given all of that.

`LsmCertGuardProgram.{hpp,cpp}` implements `IHookModule` (see `../CLAUDE.md`) and does the real `/proc/<pid>/exe` identity check in `parseEvent()`; `lsm_cert_guard.bpf.h` / `lsm_cert_guard_event.h` are the BPF-side program (comm-based pre-check only — see above) and its raw event struct. Classified by `detectors/cert_access/CertAccessDetector.hpp`, registered under `HG_SOURCE_LSM_CERT_GUARD` in `main.cpp`.
